# GAME 06 「골목 원정대」 기획서 v1.0 (개발용 상세판)

작성 2026-09-13 · 성공 기준: **가족이 반복해서 노는 것**

방범대 설계 문서(`somsom-city-game/docs/defense-design.md`)의 구성과 규격을 승계합니다. 화면 스펙, 크기 시스템, 선언형 데이터 스키마, 멀티샷 에셋 생산 원칙을 그대로 따릅니다.

---

## 1. 서비스 개요

### 1.1 한 줄

끼토가 골목을 달립니다. 구간마다 친구가 한 명씩 합류하고, 합류한 친구가 능력을 하나씩 얹어 줍니다. 스테이지 끝까지 가면 별을 받습니다.

### 1.2 왜 이 게임인가

「끼토의 하루」 포스트모템에서 나온 기준 다섯 개를 통과하도록 설계했습니다.

| 기준 | 이 설계에서 |
|---|---|
| 한 판 5분 이내 | 스테이지 1판 90~150초 |
| 행동에서 결과까지 3초 이내 | 즉시 (아케이드 조작) |
| **판이 그 자리에서 완결** | 스테이지 클리어 + 별 3개. 랭킹을 안 올려도 끝남 |
| 매 판 조금씩 다름 | 동료 합류 순서 · 갈림길 카드 · 장애물 시드 |
| 플레이하면 삽화가 열림 | 합류 컷과 갈림길 카드가 도감에 영구 해금 |

세 번째가 가장 중요합니다. 방범대가 이걸 지켜서 랭킹 없이도 굴러갑니다.

### 1.3 기존 게임과의 관계

| 게임 | 핵심 동사 | 이 게임과의 차이 |
|---|---|---|
| 낙엽피하기 | 피한다 | 조작은 같지만 **동료 조합**이 있습니다 |
| 달리기 | 뛰어넘는다 | 조작이 다릅니다 (탭 점프 vs 좌우 이동) |
| 짝맞추기 | 기억한다 | 전혀 다름 |
| **방범대** | **배치하고 지킨다** | 방범대는 앉아서 하는 전략, 이건 달리는 반사신경. **정면 경쟁 안 함** |

방범대는 이 프로젝트의 주력작입니다. 원정대는 그걸 대체하지 않고, **방범대를 하기엔 시간이 없을 때 켜는 2분짜리**를 맡습니다.

## 2. 캐릭터 크기 시스템

방범대 §2의 세계관 신장 기준을 그대로 씁니다. 필드가 타일이 아니라 자유 이동이므로 표시 크기만 조정합니다.

| 캐릭터 | 세계관 신장 | 스케일 | 표시 크기(px) | 이 게임에서의 반영 |
|---|---|---|---|---|
| 끼토 | 125cm (귀 포함 140) | 1.0 | 56×74 | 플레이어. **히트박스는 귀를 뺀 44×46** (낙엽피하기 hitScale 전례) |
| 보늘 | 145cm | 1.2 | 70×70 | 합류 시 화면 왼쪽에 같이 달림. 가장 큼 |
| 람다 | 118cm | 0.95 | 58×60 | 꼬리가 뒤로 휘날림 |
| 라칠친 할머니 | ≈116cm | 0.9 | 56×64 | 달리지 않고 5층 창문에서 내려다봄 (합류 연출이 다름) |
| 미개 | 30cm | 0.65 | 38×40 | 끼토 발치를 따라다님 |
| 북거씨 | 저상·네발 | 높이 0.85 / 폭 1.3 | 76×50 | 가로로 긴 실루엣 |

**동료는 히트박스가 없습니다.** 장애물에 맞는 건 끼토뿐입니다.

동료는 처음에 끼토 뒤를 따라가게 만들었는데, 실기에서 **끼토가 완전히 가려졌습니다.** 좌우로 벌려 세우는 방식으로 바꿨습니다. 배치는 `[-56,-8] [+56,-8] [0,-46]`, 크기는 78%, 투명도 55%이고 끼토보다 먼저 그립니다.

- 렌더 규칙: 스프라이트 하단 기준 정렬. `trimCanvas`로 투명 여백 제거 (방범대 문서의 '공중에 뜸' 이슈 재발 방지).

## 3. 화면 스펙 (420×680)

방범대와 같은 해상도입니다.

```
┌────────────────────────────┐  0
│ HUD  60px                  │     ❤❤❤   🌰 24   380m
├────────────────────────────┤  60
│                            │
│                            │
│   필드 540px               │     세로 스크롤 (위→아래로 장애물이 내려옴)
│                            │     끼토는 하단 고정, 좌우로만 이동
│                            │
│                            │
├────────────────────────────┤  600
│ 동료 독 80px               │     [보늘] [ ] [ ]   합류한 순서대로 채워짐
└────────────────────────────┘  680
```

### 3.1 상태 머신

```
BOOT → TITLE → STAGE_SELECT → RUN ⇄ FORK → (CLEAR → RESULT) | (FAIL → RESULT) → STAGE_SELECT
                     ⇅
                  LOBBY (동료 강화)
```

`FORK`는 갈림길 카드 화면입니다. 여기서만 시간이 멈춥니다.

### 3.2 화면별 사양

**1. 타이틀** — 로고, 단체 키비주얼, [골목으로] / 무한 골목 / 동료 강화 / 🔊

**2. 스테이지 선택** — 노드 64px+, 별점·잠금 표시, 다음 해금 동료 예고, 도토리 잔액

**3. 인게임**
- HUD 60px: 체력 하트 3칸 · 도토리 수 · 현재 거리
- 필드 540px: 세로 스크롤. 끼토는 y=520 고정, x만 이동
- 동료 독 80px: 3칸. 합류하면 초상화가 켜지고 능력 아이콘이 뜸

**4. 갈림길 (FORK)** — 카드 3장이 가로로. 각 카드 = 삽화 + 한 줄 + 효과 한 줄. **3초 안에 안 고르면 가운데가 자동 선택** (흐름 유지)

**5. 결과** — 별점 연출 → 도토리 획득 → 동료 리액션 말풍선 → [다음/재도전/📸 자랑하기]

**6. 로비(동료 강화)** — 방범대 로비 문법 승계. 카드 = 등급 도토리 5칸 · 능력 수치 · 다음 강화 효과 · 누적 출전

### 3.3 조작

코드를 확인한 결과 기존 두 아케이드 게임의 조작이 서로 다릅니다.

| 게임 | 조작 | 구현 |
|---|---|---|
| 낙엽피하기 | 화면을 좌우로 문질러 이동 | `touchmove` + `clientX`, 키보드 좌우 화살표 |
| 달리기 | 탭하면 점프 (원버튼) | `touchstart`, 키보드 위 화살표 |

**원정대는 낙엽피하기 방식을 씁니다.** 피하면서 줍는 게임이라 좌우 이동이 맞고, 이 집에서 가장 많이 돌아간 조작입니다. 새로 배울 게 없습니다.

### 3.4 피드백 (방범대 §8.3 승계)

파일 없이 WebAudio로 합성합니다(낙엽피하기와 같은 방식). 구현 완료.

| 이벤트 | 소리 | 햅틱 |
|---|---|---|
| 도토리 획득 | 또로롱 (2음) | 8ms |
| 황금 도토리 | 또로롱 (4음 상승) | 8ms |
| 피격 | 퍽 + 화면 흔들림 | 40ms |
| 북거씨가 막음 | 슉 (상승) | 15ms |
| 물웅덩이 | 첨벙 (하강) | 12ms |
| 할머니 회복 | 띵 (상승) | — |
| 동료 합류 | 도미솔 | 20ms |
| 갈림길 선택 | 퐁 | 10ms |
| 스테이지 클리어 | 팡파레 (4음) | 20ms |
| 별 3개 | 추가 반짝 (0.5초 뒤) | 30ms |
| 실패 | 하강 3음 | — |

음소거는 타이틀의 🔊 버튼이고, 허브 공용 키 `somsom_muted`를 씁니다. 다른 게임에서 끄면 여기서도 꺼집니다.

모바일 자동재생 정책 때문에 첫 조작에서 `AudioContext`를 깨웁니다.

접근성: 색약 모드(장애물을 색+형태로 2중 구분), 햅틱 ON/OFF.

## 4. 동료 다섯

끼토는 항상 참여합니다. 나머지 다섯 중 **판마다 3명이 무작위 순서로** 나옵니다.

| 동료 | 능력 | Lv1 | Lv2 | Lv3 | 세계관 근거 |
|---|---|---|---|---|---|
| **보늘** | 느려짐 | 0.85배 | 0.80배 | 0.75배 | 나무늘보. 느린 게 이 캐릭터의 전부 |
| **미개** | 자동 획득 | 반경 40px | 60px | 80px | 작고 빠른 개미 |
| **람다** | 도토리 배수 | 1.5배 | 1.8배 | 2.2배 | 도토리 상점 주인 |
| **북거씨** | 피격 방어 | 1회 (쿨 25s) | 1회 (쿨 18s) | 2회 (쿨 18s) | 등딱지 |
| **할머니** | 체력 회복 | 즉시 +1 | +1, 30s마다 재충전 | +1, 20s마다 | 5층 창문에서 내려다봄 |

### 4.1 조합이 재미를 만듭니다

- **보늘 + 북거씨** — 느리고 단단합니다. 초보용, 안정적으로 완주
- **람다 + 미개** — 도토리가 폭발합니다. 별 ②(도토리 목표) 노릴 때
- **할머니 + 보늘** — 오래 버팁니다. 무한 골목용
- **북거씨 + 미개 + 람다** — 방어하며 쓸어담는 욕심 조합

누가 언제 올지는 시작할 때 모릅니다. **로비에서 도토리 300을 쓰면 한 명을 지목**할 수 있고, 나머지 2명은 무작위입니다.

### 4.2 합류 연출

구간이 끝날 때 삽화 한 컷이 **1.2초** 뜹니다. 길면 흐름이 끊깁니다. 컷은 막간극 삽화(`b1_`~`b4_`, `i1_`)에서 캐릭터별로 고릅니다.

할머니만 다릅니다. 달리지 않고 5층 창문이 화면 위쪽에 나타나 손을 흔듭니다.

## 7. 갈림길 카드

구간(200m)마다 3장이 뜹니다. **여기가 유일하게 머리를 쓰는 지점**이고 삽화가 가장 많이 소비되는 곳입니다.

| 종류 | 예시 | 효과 |
|---|---|---|
| 길 | 「은행나무 밑으로」 | 다음 구간 장애물 -30%, 도토리 -30% |
| 길 | 「비 오는 골목으로」 | 장애물 +30%, 도토리 +80% |
| 물건 | 「왕금박 볼록 단추」 | 도토리 +15 |
| 물건 | 「북거씨의 시향지」 | 다음 피격 1회 무효 |
| 만남 | 「할머니의 쑥떡」 | 체력 +1 (최대 초과 불가) |
| 사건 | 「미개를 잃어버렸다」 | 다음 구간 미개 능력 정지. 완주 시 도토리 +30 |
| 사건 | 「보늘이 앞장선다」 | 다음 구간만 속도 0.7배, 도토리 -20% |

카드 그림은 `assets/day/`의 계절 컷을 그대로 씁니다. **새로 그릴 게 없습니다.**

**3초 안에 안 고르면 가운데가 자동 선택됩니다.** 아이가 플레이할 때 멈춰 서지 않게 하기 위해서입니다.

### 8.1 점수 (무한 골목 전용)

점수 = 거리(m)
     + 도토리 × 3

스테이지에서 모은 도토리가 허브 잔액(`somsom_stats.coins`)에 더해집니다. 다른 게임과 같은 지갑입니다.

## 9. 랭킹 — 조용히, 강제 없이

`docs/RANKING_SPEC.md`의 공용 규격을 따릅니다. 핵심만 옮기면:

- **버튼이 없습니다.** 판이 끝나면 결과 화면을 그리면서 뒤에서 조용히 올립니다.
- 실패해도 아무 일 없습니다 (`catch` 후 무시).
- 점수형(`expedition_scores`)은 무한 골목만. 진도형(`expedition_progress`)은 별 합계와 최고 구간.
- 진도형은 문서 ID를 닉네임으로 고정해 한 사람당 한 줄만 남깁니다.

**같이 플레이하지 않아도 서로 얼마나 했는지 보이는 것**이 목적입니다. 점수를 올리라고 재촉하는 게 아닙니다.

## 14. 리스크

**하나. 낙엽피하기와 너무 비슷합니다.**
조작이 같은 건 의도지만, 너무 같으면 "낙엽피하기 하지 뭐"가 됩니다. 차별점은 **동료 조합**이어야 합니다. M0에서 동료를 빼고 만드는 이유가 여기 있습니다. 동료 없이도 재미있으면 코어가 튼튼한 것이고, 동료를 넣었을 때 확 달라지는지 바로 비교됩니다.

**둘. 갈림길이 흐름을 끊습니다.**
화면이 멈추는 유일한 지점입니다. 3초 자동 선택으로 완화했지만, 200m마다 뜨면 잦을 수 있습니다. M1에서 300m로 늘릴지 판단합니다.

**셋. 동료가 화면을 가립니다.**
3명이 따라다니면 장애물이 안 보일 수 있습니다. 반투명 70%와 끼토 뒤쪽 배치로 완화했지만, 실기에서 확인이 필요합니다.

**넷. 또 안 할 수 있습니다.**
가장 큰 리스크입니다. M0 게이트를 반드시 지켜야 합니다.
